## PASS criteria (gate, ledger M3)

- Reference set >= 200 queries in both runs and >= 50 `global` queries (per-scope minimum), >= 3 principals (>= 1 non-admin).
- `global` scope: doc-level delta `d_recall@10` >= +0.05 with paired-bootstrap CI lower bound > 0 (replaces the passage criterion).
- `fact` scope: delta `p_ndcg@10` >= -0.005 (the router must cost fact questions nothing); judge and ACL rules unchanged. Instead of the `p_recall@100` guard, `global` scope guards doc-level `d_recall@40` (delta >= -0.005): the global candidate list is capped at 40 documents (ledger I7).
- Budgets: router call p95 <= 1500 ms (`router_timeout_s`), global answer <= `global_timeout_s` (90 s).

## Router overhead (measured, heuristic path)

In-process, 2000 questions of mixed shapes: p50 about 0.002 ms, p95 about 0.06 ms (`tests/test_router.py`).
Only ambiguous questions of >= 8 words reach the small model, and only when `router_llm=true`.

## Latency (fakes, recorded in tests/test_router_api.py)

Time to first SSE byte for a global question (classify + candidates, no LLM; map 250 ms/call behind it): p50 about 5 ms,
p95 about 9 ms. The map runs inside the stream with progress frames; no DB connection is held during it.
