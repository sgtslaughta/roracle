# P6 Web Chat, Uploads & Contract Reconciliation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Ask view as approved in the prototype (streamed, cited answers with sidenotes that open the reader at the cited passage, reader-aware context, history, share, export, ratings), plus a frontend that matches the real P3 API, including the `needs_title` flow for users and admins.

**Architecture:** New `src/features/ask/` (API hooks, SSE stream client, answer renderer, sidenotes, thread, composer, actions). Answers render Markdown + KaTeX through `react-markdown` (no raw HTML) with a small remark plugin that turns `[n]` markers into citation buttons. Streaming uses `fetch` + `ReadableStream` (EventSource cannot send the bearer header) and shares `apiFetch`'s auth hooks. P4 is being built in parallel: the UI is written against the P4 plan contract and exercised through MSW (`src/mocks/chat.ts`) under `VITE_MOCK=1`.

**Tech Stack:** P5 stack + `katex`, `react-markdown`, `remark-gfm`, `remark-math`, `rehype-katex` (all bundled; KaTeX fonts ship through Vite, no CDN).

**Spec:** `docs/spec.md` §5 (chat, reader-aware), §6 (links), §11 (UI); ADR-0012; prototype `docs/prototype/roracle.html` (Ask view = reference layout); P4 plan Global Constraints + Task 3/4; P3 final review "P6 UI-contract delta list".

## Global Constraints

- All P5 Global Constraints apply (tokens, bundled fonts, no CDN, `OverflowList` for every unbounded list, keyboard, a11y, files < 500 lines).
- Checks before every commit (from `frontend/`): `corepack pnpm lint` (= `tsc --noEmit`), `corepack pnpm exec vitest run` (no warnings), `corepack pnpm build`, `corepack pnpm check:dist`.
- Chat contract (P4, mirrored in `src/api/chat.ts` types):
  - `POST /chats {title?, scope?, model?}` → `Chat`; `GET /chats` → `ChatSummary[]` newest first; `GET /chats/{id}` → `ChatDetail` (chat + `messages[]` + `is_owner`); `PATCH /chats/{id} {title?, scope?, pins?, excludes?}` → `Chat`; `PUT /chats/{id}/shares {users: string[], groups: string[]}`; `GET /chats/{id}/export.md` (text/markdown); `PUT /messages/{id}/rating {value: 1|-1, comment?}`.
  - `POST /chats/{id}/messages {content, viewer, model?}` → `text/event-stream`, events `token {text}`, `citations {items: Citation[]}`, `done {message_id}`, `error {detail}`. Unknown model → 422 before streaming.
  - `Citation = {n, doc_id, version_id, version?, chunk_id, title, page, bbox, quote, available?: true} | {n, available: false}`.
  - Viewer body exactly `{"tabs": [{"doc_id", "version_id", "page"}] (≤ 3), "ignored": [doc_id], "selection": {"doc_id", "page", "text"} | null}`.
  - Scope `all` | `collection:<id>` | `open`. Models from `GET /chats/models` → `{models: string[], default: string}` (contract gap, see FINAL).
- Citation markers `[n]`, `[2,3]`, `[2][3]` render as `<sup>` buttons; an unknown `n` renders as plain text. Unavailable citations render "Source not available" and are not clickable.
- Click on a marker or sidenote → `openDoc(doc_id, {page, chunkId, version, bbox})`.
- Ratings: thumbs up/down (`ThumbsUp`/`ThumbsDown`), never chevrons. Votes stay thumbs.
- `needs_title` is a terminal, attention-needing stage: the uploads row prompts the owner for a title (`PUT /documents/{id}/versions/{vid}/title`); admins see a "Waiting for a title" queue (`GET /admin/needs-title`) on My uploads and can set titles there.
- Mock: `VITE_MOCK=1` serves chats (one seeded chat from the prototype), streams tokens ~30 ms apart, emits citations for the sample docs incl. one `available:false`. Mock admin flag: `localStorage["roracle-mock-admin"]="1"` (try/catch).

## Review Focus

1. SSE parser handles events split across chunks, `\r\n`, multi-line `data:`, and a 401 before the stream (one renew then sign-in) — Task 2.
2. Viewer state never exceeds 3 tabs, respects ignored docs, and maps reader version numbers to version ids — Task 2.
3. No raw HTML from answers or search highlights reaches the DOM except `<em>` (search) and KaTeX output — Tasks 1, 3.
4. Sidenotes align to their markers without overlapping; at narrow widths they stack under the answer — Task 3.
5. Abort (new chat / navigate away / Stop) cancels the fetch and leaves a partial answer marked interrupted — Task 4.
