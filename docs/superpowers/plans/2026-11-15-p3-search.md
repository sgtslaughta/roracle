# P3 Search & Access Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Users search their accessible library with hybrid retrieval, filters, facets, sorting and paging; open documents and versions; vote, tag, collect, share; and follow in-library references and "cited by" links.

**Architecture:** All Elastic queries go through one ACL filter builder that mirrors P1's SQL `visible_documents` (ADR-0002). BM25 and kNN run separately and are fused with RRF in Python (ADR-0007); optional reranker over the fused top 50; results grouped per document; vote multiplier applied after fusion. Votes, tags, collections, shares and citations live in Postgres; their search-relevant projections are copied onto chunk documents.

**Tech Stack:** P2 stack + `rapidfuzz` (reference title matching).

**Spec:** `docs/spec.md` §3, §4 step 9, §5, §6; ADR-0002, 0007.

## Global Constraints

- RRF: `score = Σ 1 / (60 + rank)` over the BM25 and kNN lists (rank starts at 1); each list size 100.
- Vote multiplier (user decision 2026-11-15): `1 + 0.15 * clamp((vote_ratio(up, down) - 0.5) * 2, -1, 1)`, `vote_ratio = (up + 1) / (up + down + 2)` (no votes = neutral; every upvote helps, every downvote hurts).
- Document score = best chunk fused score × vote multiplier; up to 2 highlighted passages per document.
- Rerank only when `ROR_RERANK_URL` is set (POST `{model, query, documents}` → `results[{index, relevance_score}]`); otherwise skip silently.
- Facets: `tags`, `year`, `file_type`, `org_unit`, `collection`, `author`, computed from the ACL-filtered matched set (top 200 documents) — never from unfiltered data.
- Sorts: `relevance`, `newest`, `votes`, `title`. Page size 20 (max 50).
- Downvote reasons exactly: `outdated`, `wrong`, `low_quality`, `superseded` (`superseded` requires `superseded_by` doc id). New version of a document deletes its `outdated` reasons (votes stay).
- Tag normalization: lowercase, runs of non-alphanumerics → `-`, trimmed of `-`, 1–40 chars.
- `org_unit` branch: `visibility == org_unit AND org_unit IN org_ancestors(p.groups)` (P1 `roracle.access.org_ancestors`; always includes `/`) → ES `terms` on keyword `org_unit`. Never prefix/wildcard queries.
- Not visible ⇒ `404` with body `{"detail": "not found"}` for every document-scoped endpoint (no existence leak).
- Reference matching: DOI exact (case-insensitive) first; else `rapidfuzz.fuzz.token_sort_ratio(title) ≥ 92` and same year.

## Review Focus

1. A query whose best matches are all invisible must return zero results **and** zero facet counts — Task 1/2.
2. `org_unit` visibility with sibling paths (`/Math` vs `/Mathematics`) — Task 1 parity test.
3. Changing visibility/shares updates the ES ACL fields before the request returns — Task 6.
4. Empty or whitespace query → library browse (newest first), not an error — Task 2.
5. Citation resolution never links to a document the viewer cannot see (cited-by lists are ACL-filtered at read time) — Task 5.

### Task 2: Hybrid retrieval core

**Files:** Create `backend/src/roracle/retrieval.py`; Test `tests/test_retrieval.py` (unit, fakes) and `tests/test_retrieval_es.py` (integration).
**Interfaces:**
- `rrf(lists: list[list[str]], k: int = 60) -> dict[str, float]`; `vote_ratio(up: int, down: int) -> float`; `vote_multiplier(up, down) -> float`.
- `@dataclass Passage(chunk_id, doc_id, version_id, text, highlight, pages, bboxes, score)`
- `search_chunks(es, llm, settings, p, query: str, *, filters: dict, doc_ids: list[str] | None = None, size: int = 100) -> list[Passage]` — BM25 (`multi_match` on `text^1, title^2, headings`) + kNN (`num_candidates = 4 × size`), both with `acl_filter` and filters; fused; optional rerank of top 50.
- `@dataclass DocHit(doc_id, title, authors, year, score, passages: list[Passage])`; `group_by_document(passages, votes: dict[str, tuple[int, int]]) -> list[DocHit]`.
- [ ] Unit tests: rrf ordering example `[["a","b"],["b","c"]] → b > a > c`; `vote_multiplier(0,0)=1.0`; multiplier bounds 0.85–1.15; grouping keeps ≤ 2 passages per doc and applies multiplier. Integration: query term only in an invisible doc → `[]`.
- [ ] **Commit** `feat(search): hybrid BM25+kNN retrieval with RRF and vote boost`

### Task 4: Search and document APIs

**Files:** `api/routes/search.py`, `api/routes/documents.py` (extend); Test `tests/test_search_api.py`.
**Interfaces:**
- `GET /search?q=&tags=&year=&file_type=&org_unit=&collection=&author=&sort=relevance&page=1&size=20` → `{"total", "page", "results": [DocHit + tags + votes {up, down, mine} + file_type + version], "facets": {name: [{value, count}]}}`.

- `GET /documents/{id}/versions/{n}/file` → original bytes (`Content-Disposition` with original filename, RFC 5987 encoded); `GET /documents/{id}/versions/{n}/docling` → parsed JSON (for the reader's passage boxes).
- [ ] Tests: facet counts only include visible docs; sort `newest`; empty `q` browses; 404 for invisible doc on every endpoint; download filename with unicode.
