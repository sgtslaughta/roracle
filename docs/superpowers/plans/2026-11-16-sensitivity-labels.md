# P13 Sensitivity Labels Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Roadmap note (plan-level only, not in spec §13):** | 13 | Sensitivity labels | Admin-ordered labels on documents + notes, per-label policy gates (LLM context, agents/handoffs, export, reason-on-lower), badges/picker/facet/admin page | — runs after the polish branch (`feat/polish-fixes`) merges; base = main + P11b + polish.

**Goal:** Admins define an ordered set of sensitivity labels; every document (incl. drafts) carries one and every note may raise it. Labels are displayed everywhere and drive four per-label policy gates — (a) excluded from LLM context and LLM judges, (b) invisible to agents (PAT/MCP) and handoffs, (c) no download/export, (d) reason required when lowering. Labels never widen access: visibility/shares remain the only access control.

**Architecture:** New package `roracle/labels/` (`policy.py` immutable per-request `Policy` + SQL/ES clause builders, `service.py` CRUD + set/raise/lower + notifications/audit) and `models_labels.py` (imported by `models.py`; `models.py` is already 534 lines). REST in `api/routes/labels.py` (`GET /labels`, doc/note label PUTs) and `api/routes/admin_labels.py`. Gate (b) is enforced centrally in `access.visible_documents(p)` (PAT principals) + `search_acl.acl_filter(p, policy)`; gate (a) in `chat/retrieve.py`, `notes/community.py`, `writing/cite_check.py`, `writing/validate.py`, `ingest/summary` call site; gate (c) in a single `labels.policy.require_exportable(...)` helper called by every download/export route. ES chunks carry `label_id` (keyword) via `search_index.acl_fields`, converged by the existing `acl_sync` job.

**Tech Stack:** P10/P11b stack, no new dependencies.

**Spec:** `docs/spec.md` §3 (access), §5 (retrieval/chat), §7 (agentic, handoffs, proposals), §8 (writing), §9 (admin), §10 (notifications); ADR-0002 (app-injected ES ACL), ADR-0010; new ADR-0014 (Task 7). User decisions 2026-11-16 (memory `roracle-design.md` "Sensitivity labels") are binding.

## Global Constraints

- Migration `0011_labels.py`: `revision = "0011"`, `down_revision` = whatever `alembic heads` prints at execution (expected `"0010"`; if the polish branch added `0011`, take the next number). Exactly one head after upgrade.
- Label fields: `name` 1–40 chars unique (case-insensitive), `colour` `^#[0-9a-fA-F]{6}$`, `description` ≤ 500, `rank` int unique (higher = more sensitive), gates `exclude_llm`, `block_agents`, `block_export`, `reason_on_lower` (bool, default false), `is_default` (exactly one true). Max 20 labels.
- **Monotonic gates (validated on every admin write, 422 `{"detail":"gates must not decrease with rank"}`):** for each gate, if label L has it, every label ranked above L has it. Hence "raise" can never escape a gate, and `effective = max(doc, note)` gates ⊇ both.
- **Labels never widen access.** Every label check is an extra AND on top of `visible_documents` / `readable_notes`; no code path may OR a label condition into visibility.
- Who may change a label (doc: owner/admin; note: author/admin): **raise or equal** → allowed; **lower** → admin only, else 403 `{"detail":"only admins can lower a label"}`; reason (3–500 chars) required when lowering and the *current* label has `reason_on_lower`, else optional; every change audited. All label write routes `require_human` (PAT → 403 `{"detail":"agents must propose"}`).
- Not-visible stays 404 `{"detail":"not found"}`. Gate (b) makes a doc/note *not visible* to PAT principals (404, dropped from lists/search/facets/counts — no "blocked" hint). Gate (c) on a visible doc → 403 `{"detail":"export blocked by label","label":"<name>"}` (no leak: caller can already see the doc).
- Label JSON (everywhere a label is shown): `{id, name, colour, rank, gates: {exclude_llm, block_agents, block_export, reason_on_lower}}`. Document JSON adds `label`; note JSON adds `label` (own, nullable) and `effective_label`.
- Audit actions (detail never contains document/note text): `label.create`, `label.update`, `label.delete`, `label.reorder`, `document.label` `{from, to, reason?, via: "user"|"admin"|"proposal"|"near_dup"|"submit"}`, `annotation.label` (same detail), `label.export_blocked` `{route}`.
- Notification kind `label.changed` `{document_id, annotation_id?, from, to, by}` to the document owner / note author whenever the actor is someone else.
- Files < 500 lines; ruff check + format clean; integration tests under `flock /tmp/roracle-integ.lock`.

## Review Focus

1. No path widens access; PAT principals never see `block_agents` docs/notes (REST, MCP search/get/passages/ask, list_annotations, handoff manifests, cite_check key resolution, counts/facets) — Tasks 3, 5.
2. `exclude_llm` content never reaches an LLM prompt: chat (ranked, open tabs, selection, pins, community notes), MCP `ask`, cite_check judge, style check, ingest summary — Tasks 3, 4.
3. `block_export` enforced on every byte-serving route (file, pdf, docling, bibtex, chat `export.md` passages, evidence file, draft build) — Task 3.
4. Lowering is admin-only + reason rule + audit + owner notified; agents only propose — Tasks 2, 4, 5.

## Rulings (plan-level)

- R1 Storage: `labels` table + `documents.label_id` **NOT NULL** FK (RESTRICT) + `annotations.label_id` nullable (null = inherit) + `connectors.label_id` nullable (null = global default). Migration seeds one label `General` (rank 0, colour `#496580`, no gates, default) and backfills all documents — cost: none; admins rename it.
- R2 Versions: label is per **document**, not per version (a label describes the work; per-version labels would let an old version leak via the versions list). New versions keep the label; the upload form may raise it — cost: cannot label one version more strictly than another.
- R3 Drafts: drafts are documents, so they carry a label from creation (global default, or `label_id` on create). Submit accepts optional `label_id`; result = max(current, requested, profile `default_label` if the writing profile YAML names an existing label) — submit can never lower (non-admin). Profiles referencing an unknown label → ignored with a warning in validate — cost: profile YAML gains one optional key.
- R4 Uploads/connectors: upload (REST + MCP `upload`) takes optional `label_id`, must rank ≥ default (choosing lower = lowering → admin only); connector-ingested docs get `connector.label_id` or the global default — cost: none.
- R5 Near-dup `new_version` merge and polish T4 note merge: target doc label = max(target, incoming upload's chosen label), audited `via:"near_dup"`; merged notes keep their own labels — cost: a merge can raise but never lower.
- R6 ES projection: index `label_id` (keyword), not rank. Gate sets are resolved at query time from `Policy` (`must_not terms label_id`), so reorder/gate edits need **no reindex**; only a document's label change needs `acl_sync` (same immediate-sync + `durable_job` path as `documents_write`). Migration enqueues one `acl_sync` job per non-deleted document (SQL `INSERT INTO jobs … SELECT`); until converged, ES lacks the field and the R19 Postgres post-filter (which also applies the gates) is the authority — cost: brief over-fetch, never a leak.
- R7 `search_acl.acl_filter(p, policy)` gains a **required** `policy` argument (3 call sites: `retrieval.py`, `mcp/server.py`, `writing/cite_check.py`); for `p.via == "pat"` it adds `must_not terms label_id: policy.ids("block_agents")`. SQL mirror: `access.visible_documents(p)` adds `Document.label_id NOT IN (SELECT id FROM labels WHERE block_agents)` for PATs — cost: one subquery per visibility check.
- R8 Gate (a) scope: chat/`ask` retrieval adds `must_not terms label_id: ids("exclude_llm")` + PG post-filter; explicitly requested context (open tabs, selection, pins) from excluded docs is dropped and reported as `excluded_by_label: [{doc_id, label}]` in the chat response/SSE `meta`; community/note passages use the effective label. cite_check: citing an excluded doc → item verdict `unchecked`, reason `"label excludes LLM review"` (warning, ackable, not blocking). A draft whose own label excludes LLM → style check and every cite judge skipped (`unchecked`), validate warns once. Ingest: LLM summary skipped for docs whose label (at ingest time) excludes LLM; embeddings still computed (embedding model is not a generative context). Existing summaries are not deleted on later raise. Past chat answers are not retro-redacted for their owner — cost: documented in security.md.
- R9 Gate (c) applies to everyone except the document owner and admins (owner holds the original; admins can relabel anyway). Routes: `GET /documents/{id}/versions/{n}/file|pdf|docling`, `GET /export/bibtex` + MCP `export_bibtex` (gated docs silently omitted, like invisible ones), `GET /chats/{id}/export.md` (passage text of gated docs replaced by `[withheld: <label>]`), `GET /evidence/{id}/file` (effective note label), draft `build_pdf` (owner → allowed). Each block audited `label.export_blocked` — cost: owners can still export their own labelled work.
- R10 Handoffs: `block_agents` docs/notes are excluded from handoffs for **every** loader (a handoff is an agent context package): dropped at `create` and redacted at `view`, counted in `withheld` exactly like invisible sources. Manifest items carry `label` — cost: humans loading a handoff in the UI also see them withheld.
- R11 Notes: `annotations.label_id` null = inherits; set/raise by author, lower only admin (never below the doc label — 422). `effective_label = max(doc, note)` computed in `notes/service.to_json`; `readable_notes(p)` adds the gate (b) clause for PATs on the effective label. Proposals created by agents default to null (inherit).
- R12 Agents only propose: `proposals.kind` CHECK adds `'label'`; payload `{document_id, annotation_id?, label_id, reason?}`; approval re-runs `service.set_*_label` as the approver (so an owner approving a *lowering* proposal gets 403; admins may approve with reason), audited `via:"proposal"`.
- R13 Label CRUD: delete only if unused by any document/note/connector and not default, else 409 `{"detail":"label in use"}`; reorder `PUT /admin/labels/order {ids}` must list every label; rank edits re-validate monotonic gates; setting `is_default` unsets the previous one in the same transaction. No retire/merge in this plan.
- R14 Not a classification system: labels are advisory handling markers enforced only inside rOracle; no clearance model, no export-control or regulated-data guarantees, no label propagation into derived files outside the gates above. Exact ruling text goes into security.md + ADR-0014 (Task 7).
