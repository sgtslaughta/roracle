## Global Constraints

1. **Truth comes from code, not from the spec, plans or other docs.** Every factual statement must be traceable to code in the merged tree: setting names and defaults, routes, roles and scopes, label gates, limits, metric names, audit actions, job kinds, Helm keys and Terraform variables. Spec, ADRs and plans only say *why*.
2. Every Markdown file is **≤ 500 lines** (CI enforced). Split by topic and link from a section `README.md`.
3. **Air-gap safe.** CI makes no external calls and adds no new tooling outside the PyPI or npm mirrors. Docs never tell readers to fetch from the internet except in the "build the mirror" section of `airgap-mirror-manifest.md`.
4. **Names:** use "rOracle" in prose and `roracle` in code, hosts and packages. Env vars always appear as `ROR_<UPPER>`. Routes appear exactly as in `openapi.json` (for example `/api/...`).
5. **Do not invent features.** If behaviour is unclear, read the code or tests. If it is still unclear, write `> TODO(verify): …` and list it in the task report. The reviewer either resolves it or the line is removed before merge.
6. **No secrets or real hostnames.** Use `example.internal` and placeholders.
7. Diagrams are Mermaid fenced blocks only, with no images. The C4 diagrams use `flowchart` with subgraphs (C4 syntax is experimental in GitLab Mermaid).
8. Commits follow semantic commits (`docs(…)`, `ci(docs)`, `build(docs)`). This is a docs-only phase, so `VERSION` does not change unless T1/T2 change shipped code paths (scripts are not shipped, so no bump). Every commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
9. Before each commit, `scripts/docs/check.sh` passes, along with the existing lint (ruff, mypy, pnpm lint) if any `.py` or `.ts` file changed.
10. Single writer per file. Tasks list the files they own. Others may only add a link line to `docs/README.md` (T3 owns it; later tasks append to it in their own commits).

## Review Focus (applies to every reviewer)

- **Claim audit:** extract every checkable claim into a table (claim → `path:line` evidence → ✅/❌). Spot-check at least 30 claims per task, or all of them if there are fewer. Any ❌ is Important.
- Pay most attention to security-relevant statements: ACL and visibility, R19 Postgres re-check, label gates (`exclude_llm`, `block_agents`, `block_export`, downgrade reason), PAT scopes, rate limits, audit coverage, TLS and network policies. An overstated guarantee is Critical.
- Defaults and limits must match `backend/src/roracle/config.py`, `runtime.py`, `deploy/helm/roracle/values.yaml` and `deploy/terraform/variables*.tf` exactly.
- Audience fit: the user guide has no kubectl or env vars. The ops docs do not explain UI clicks.
- Links resolve, there are no orphan pages (each page is linked from a section README), and no file is over 500 lines.
- Nothing stale should mention: MinIO tenant/operator in prod, ES 8.x as current, chart 0.1.x, "Valkey required", or removed settings.
