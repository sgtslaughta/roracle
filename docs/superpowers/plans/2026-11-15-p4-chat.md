# P4 Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Users ask questions over the documents they can see and get streamed answers with numbered citations to exact passages, aware of what they are reading, with persistent, shareable, exportable chat history.

**Architecture:** `POST /chats/{id}/messages` retrieves passages with P3 `search_chunks` (ACL-filtered), boosting documents open in the reader, builds a numbered-context prompt, streams the model's answer over SSE, then persists the message with resolved citations and the retrieved set. Citations are model-emitted `[n]` markers mapped back to passages server-side; unknown markers are dropped.

**Tech Stack:** P3 stack; `sse-starlette` (or FastAPI `StreamingResponse` with `text/event-stream`).

**Spec:** `docs/spec.md` §5 (chat, reader-aware), §6 (links); ADR-0007.

## Global Constraints

- Context passages: top 8 after fusion/rerank (configurable 4–12), each ≤ 1200 chars, numbered `[1]..[n]`.
- Reader-aware boost: passages from viewer docs get ×1.5; passages on the viewer's current page of an open doc ×2.0; a quoted selection is always included as passage `[0]`-equivalent context labeled "Selected passage" (cited as the doc's page).
- Viewer state body: `{"tabs": [{"doc_id", "version_id", "page"}] (≤ 3), "ignored": [doc_id], "selection": {"doc_id", "page", "text"} | null}`.
- Scope: `all` | `collection:<id>` | `open` (only viewer docs). Pins (always included if retrieved candidates exist for that doc) and excludes (filtered out) are per-chat lists of doc ids.
- System prompt (exact): "You are rOracle, a research assistant. Answer only from the numbered passages. Cite every claim with [n] markers matching the passages. If the passages do not contain the answer, say so plainly. Use LaTeX ($…$) for math."
- SSE events: `token` `{"text"}`, `citations` `{"items": [{n, doc_id, version_id, chunk_id, title, page, bbox, quote}]}`, `done` `{"message_id"}`, `error` `{"detail"}`.
- Models: request may name a model; it must be in the admin allowlist (`settings.chat_models`, comma-separated; first is default) or 422.
- Answer ratings (`+1/-1` + optional comment) are visible only to admins.

## Review Focus

1. A passage the user cannot see never reaches the prompt, even when its doc id is in `tabs` or `pins` — Task 2.
2. Model emits `[9]` with only 8 passages, or `[2,3]` / `[2][3]` forms → valid markers resolved, invalid dropped — Task 3.
3. Client disconnects mid-stream → partial answer is still saved with status `interrupted` — Task 3.
4. Shared chat link opened by a user who cannot see some cited docs → those citations render as "source not available", text unchanged — Task 4.
5. Inference endpoint error mid-stream → `error` event, message saved as `failed`, no 500 page — Task 3.
